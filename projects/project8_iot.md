## 📌 Project Overview

Cyber‑physical systems (CPS) that integrate IoT devices are increasingly vulnerable to cyber‑attacks. Traditional IT/OT security solutions often fail to address the unique challenges of CPS environments, such as real‑time constraints, heterogeneous devices, and imbalanced data.  

This project implements a **proof‑of‑concept detection and attribution workflow** using **Node‑RED** for IoT data simulation and **Splunk** for log monitoring, indexing, and alerting. By simulating both normal and malicious IoT sensor activity, the system demonstrates how SOC practices can be applied to CPS environments for proactive threat detection.  

The documentation includes detailed screenshots stored in the `project8/` folder, making the workflow examiner‑friendly and reproducible.

---

## 🎯 Objectives

- Simulate IoT sensor activity (normal vs malicious) in a CPS environment.  
- Collect logs in structured JSON format and store them in a shared folder.  
- Forward logs using Splunk Universal Forwarder to Splunk Enterprise.  
- Index logs in Splunk Enterprise for search and analysis.  
- Configure Splunk alerts to detect anomalies and malicious behavior.  
- Provide examiner‑friendly documentation with screenshots and proof artifacts.  
- Relate practical implementation to academic research on IoT‑CPS security.

## ⚙️ System Architecture

### 1. IoT Simulation with Node‑RED
Node‑RED is used to simulate IoT sensors. Each sensor is represented by an **Inject node** that generates payloads. These payloads are routed to a **File node**, which writes them into a CSV file (`iot-logs.csv`). A **Debug node** is also used to validate payloads in real time.

- **Sensor 1** → Normal payload (temperature and humidity within safe range).  
- **Sensor 2** → Normal payload (slightly varied values).  
- **Sensor 99** → Malicious payload (abnormally high values, simulating attack).  

This setup allows us to clearly distinguish between normal IoT activity and malicious behavior.

### 2. Splunk Universal Forwarder
The Splunk Universal Forwarder is configured to monitor the IoT log file and forward events to Splunk Enterprise. This is achieved by editing the `inputs.conf` file to include:
```spl
monitor://Z:\IoT-Project\logs\iot-logs.csv
```

This ensures that every new line appended to the CSV file is forwarded to the indexer.

![Inputs.conf Configuration](project8/IoT-project-inputs-conf.png)  
*Configuration of Splunk Universal Forwarder to monitor IoT logs.*

### 3. Splunk Enterprise (SIEM VM)
Splunk Enterprise acts as the central SIEM platform. It receives logs on port **9997**, indexes them into a custom index (`iot_logs`), and allows searches and alerts to be configured.

## 🔍 Sample Logs
```json
{"sensor_id":1,"temperature":25,"humidity":60}
{"sensor_id":2,"temperature":26,"humidity":58}
{"sensor_id":99,"temperature":999,"humidity":999}
```
- Sensor 1 & 2 → Normal IoT activity.
- Sensor 99 → Malicious payload (abnormally high values).

##  📊 Splunk Searches

### Normal Sensor Data
```spl
index=iot_logs sourcetype=iot_csv sensor_id=1 OR sensor_id=2
```
### Malicious Sensor Detection
```spl
index=iot_logs sourcetype=iot_csv sensor_id=99
```
### Abnormal Temperature Alert
```spl
index=iot_logs sourcetype=iot_csv temperature>80
```

## 🚨 Alerts

Splunk alerts are configured to detect malicious activity and abnormal sensor values.

- Malicious Sensor Alert  
Triggered when sensor_id=99 appears in logs.
Action: Email notification / Splunk alert dashboard.

- Abnormal Temperature Alert  
Triggered when temperature > 80.
Action: Email notification / Splunk alert dashboard.
